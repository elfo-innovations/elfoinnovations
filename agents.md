## 2. Preserve Existing Work

* Never blindly overwrite, revert, reset, or delete existing work.
* Treat the current `main` branch as the source of truth.
* Before modifying an area of the codebase, inspect the existing implementation and recent commits.
* If another agent has already implemented part of the task, continue from the current state instead of implementing it again.
* Do not use `git reset --hard` unless explicitly instructed by the project owner.
* Do not force-push (`git push --force`) unless explicitly instructed by the project owner.

## 3. Git Safety

Before committing:

```bash
git status
git diff
```

Make sure the changes belong to the task you were asked to complete.

* Do not include unrelated changes in a commit.
* Use clear, descriptive commit messages.
* If the remote branch contains newer commits, fetch and inspect them before deciding whether to merge or rebase.
* Never assume the remote is unchanged.
* Never overwrite remote work just to make a push succeed.

## 4. Cloudflare Deployment

This project is deployed through **Cloudflare's build pipeline**.

Current deployment uses:

* Build command: `npm run build`
* Deploy command: `npx wrangler deploy`

### Important npm rule

**DO NOT add `"packageManager": "npm@..."` to `package.json`.**

Cloudflare manages the npm version used during deployment.

Pinning npm in `package.json` previously caused the Cloudflare dependency-installation step to fail.

Keep the package manager version **un-pinned** unless Cloudflare compatibility with the exact npm version has been explicitly verified first.

Do not reintroduce this setting just to make local development use a specific npm version.

## 5. Cloudflare Worker Name

The actual deployed Worker name is:

```text
elfoinnovations
```

Do not change it to:

```text
elfo-innovations
```

The Worker configuration must continue targeting the existing Worker.

Before changing `wrangler.toml`, understand that a change to the Worker name can affect deployment targeting.

## 6. Deployment Changes Require Extra Care

Changes to any of these files can affect deployment:

* `wrangler.toml`
* `package.json`
* `package-lock.json`
* Cloudflare-related configuration
* build configuration
* deployment scripts

After making deployment-related changes, run the relevant local checks before pushing whenever possible.

Do not make multiple unrelated deployment changes at once. If deployment breaks, it should be possible to identify which change caused it.

## 7. Secrets and Credentials

Never commit, print, paste, or expose:

* API keys
* access tokens
* passwords
* private keys
* service-role keys
* webhook secrets
* Cloudflare secrets
* Supabase secrets
* VAPID private keys
* `.env` secrets

Use environment variables, Cloudflare secrets, Supabase Vault, or the appropriate secret-management system.

If a secret appears in logs or source code, stop and report it rather than copying it elsewhere.

## 8. Security Fixes

Do not weaken or remove existing security protections simply to make tests or deployment pass.

In particular:

* Do not remove authentication from protected endpoints.
* Do not restore broad database permissions without understanding why they were restricted.
* Do not expose Supabase service-role credentials to the client.
* Do not bypass security checks just because an AI agent considers them inconvenient.

If a security-related change is required, explain what is being changed and why.

## 9. Generated Files

Some files are automatically generated by the project tooling.

For example:

```text
src/routeTree.gen.ts
```

Do not manually rewrite or "clean up" generated files unless the task specifically requires it.

If the build or route-generation process updates a generated file, determine whether the change is expected before reverting it.

## 10. Tests and Validation

Before declaring a task complete:

* Run the relevant tests.
* Run lint/type checks when relevant.
* Run the build when the change can affect production.
* Review the final Git diff.
* Make sure no secrets or unrelated changes are included.

Do not claim that a task is complete if a required check is still failing.

## 11. Do Not Guess About Infrastructure

If something depends on Cloudflare, Supabase, GitHub, deployment configuration, or another external service:

* Inspect the actual configuration first.
* Do not assume how the infrastructure works.
* Do not invent environment variables, Worker names, project IDs, deployment pipelines, or credentials.
* If something cannot be verified, say so.
